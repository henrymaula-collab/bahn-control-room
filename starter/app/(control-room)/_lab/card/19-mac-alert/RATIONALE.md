# card 19: Mac alert

- References: Apple HIG Alerts, macOS (https://developer.apple.com/design/human-interface-guidelines/alerts, raw `research/premium/product/raw/pp/hig-alerts.md`): macOS alerts show the app's icon and can carry an accessory view; "place the default button on the trailing side"; Return answers the default. Apple HIG Buttons (raw `research/premium/product/raw/pp/hig-buttons.md`): "an ellipsis in a control title signals that people can provide additional input". Claude in Chrome's permission prompt (https://support.claude.com/en/articles/12902446-claude-in-chrome-permissions-guide, shot `research/premium/product/shots/chat-05b-claude-chrome-permission-prompt.png`): a native-feeling prompt with the default on Return.
- Borrowed: the anatomy, not the modality. A panel floating over the page (hairline ring, soft warm shadow, 18 px corners, a 250 ms drop like a sheet), Bahn's mark as the app icon, the question as the bold message, the situation and what happens next as informative text, a "Details" disclosure on the leading edge that opens an accessory view with the pickup place's own words and the kind's record, "Other options…" and the default on the trailing edge. Return sends when nothing else has the keyboard.
- Why for ops: every Mac user has answered thousands of these; the shape says "one decision, the default is the dark button on the right" before a word is read.
- Trade-off: HIG warns against alerts for common, undoable actions; this is not modal (no scrim, nothing blocked), but the panel adds a surface and its padding narrows the text.

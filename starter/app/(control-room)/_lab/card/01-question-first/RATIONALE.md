# card 01: Question first

- Reference: Apple HIG Alerts and Buttons (https://developer.apple.com/design/human-interface-guidelines/alerts, .../buttons; raw copies `research/premium/product/raw/pp/hig-alerts.md`, `hig-buttons.md`) and Daybridge's dialog that names the object (https://nicelydone.club/examples/screens/1c94992d-0688-41b0-91da-de5c651172e3, `research/premium/visual/shots/card-10-daybridge-delete-names-time.png`).
- Borrowed: the alert's order (a bold title that is the question, a regular message that explains it), the answers stacked at one width with the default on top, and Return as the default's key (a faint ↵ on the button, as Claude in Chrome's plan approval shows it, `research/premium/product/shots/chat-05-claude-chrome-plan-approval.png`).
- Why for ops: the first thing read is the thing to answer; the situation reads as its reason, so the two blocks can never run together as one heading (Henry's complaint about today's card).
- The stack keeps both answers the same size and position on every case, so the hand learns where "yes" is.
- Trade-off: scanning many cases, "what is wrong" is no longer the first line; the long questions (100 characters) take three lines at Title 1.

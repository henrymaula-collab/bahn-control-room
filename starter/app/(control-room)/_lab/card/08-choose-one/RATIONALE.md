# card 08: Choose one

- References: GitHub's review submit (https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/reviewing-changes-in-pull-requests/reviewing-proposed-changes-in-a-pull-request, raw `research/premium/product/raw/pp/gh-review.md`): Comment, Approve or Request changes as radio choices, then one "Submit review"; the purchase-request decision area (https://dribbble.com/shots/27442499, `research/premium/visual/shots/card-15-purchase-request-stepper.png`), whose board note says this is the right model when choices need one confirm.
- Borrowed: all options as radio rows with the default already chosen, one button under them; the button's words follow the choice ("Send the email", "Keep the gig unpublished"), the chosen row shows its consequence.
- Why for ops: for a newcomer the whole decision is on one screen, and the default is still a single press; the question names the car ("What should happen with the Ferrari Roma?"), never "Proceed?".
- Choosing anything but the suggestion opens the sheet on that option's reason step, so the shift lead still gets the why.
- Trade-off: every option is visible, which costs the calm of one question and one answer; with five options it would become a form.
